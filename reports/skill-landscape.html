00结论先行 EXECUTIVE SUMMARY

一句话结论

这个赛道在 2026 年已经相当成熟，但「跨境 + AI Skill」生态几乎全部围绕亚马逊运营构建，专门服务「茶叶 / 食品出口」的 skill 是空白。这既是缺口，也是你的机会 —— 与其从零造，不如站在这些仓库的肩膀上，只补自己缺的那两块：食品合规与海外买家触达。

最值得直接参考

noique/cross-border-ecommerce-skills

58 个 skill、13 条业务链，覆盖品牌战略 → 亚马逊运营 → DTC → 财务/资金 → 联盟 → 欧盟渠道 → 海外买家开发 → VOC。它内置的 「证据闸」机制（数据不足就说"数据不足"，而不是编数字）是整个生态里最值得抄的设计理念。

最值得直接复用

chnjames/tradehot-skill
+ AccioWork/agent-skills

一个做外贸情报（HS Code、关税速查、风险预警、汇率与外汇管制），一个做关税与 HS 编码查询。这两个正好补上前两份报告里最实操、最容易出错的部分，且都是单文件 SKILL.md，装即用。

最值得学习架构

clawec-agents
+ markwaveio 选品套件

前者示范了「一个 Agent 调度 N 个 API Skill」的分层结构；后者示范了把"防被假数据骗"的纪律写进 skill 本身（关键词污染自检、三源口径对齐）。这两个设计思路可直接迁移到你的选品与市场调研环节。

四个关键判断

  1. 生态高度集中，但存在结构性空白。约 70% 的高相关仓库围绕 Amazon 运营（选品、Listing、广告、VOC）。而「食品/农产品出口合规」方向的 skill 只有零星一两个，且都聚焦中国国内标准（GB 7718 标签、GB 2760 添加剂），没有做「出口目的国准入」的成熟 skill。你上一份报告里查的那些欧盟 MRL、FDA FSVP、日本肯定列表 —— 目前没有现成工具帮你自动化。
  2. 最值得学的不是功能，是「诚实机制」。两个高质量仓库都把「不编数据」写进了 skill 本身：noique 的「证据闸」要求每条事实标注来源与日期；markwaveio 内置关键词污染自检与三源口径对齐。这正是跨境分析最容易翻车的地方 —— 我也在这次调研中看到不少仓库在描述里堆砌漂亮话却无实际交付。
  3. 许可证是最大的坑。本主题下星标最高的几个中文仓库（含 1302⭐、936⭐ 的头部项目）未声明任何开源许可证。按著作权法默认「保留所有权利」，直接拿来做商业项目存在法律风险。可放心商用的是 MIT / CC0 / MIT-0 那几个（见第 05 节标注）。
  4. 技术栈高度趋同，迁移成本很低。几乎全部是「SKILL.md + references/ + scripts/」的 Markdown 驱动结构，配 MCP 取数据。这意味着你不需要懂复杂工程就能改 —— 改的就是自然语言写的工作流文档。

关于"skill 类项目"的界定

本报告覆盖三类：① Skill（SKILL.md 形式的工作流文档，给 AI 装 SOP）；② MCP Server（给 AI 接外部数据/工具的服务端）；③ Agent（可调度多个 skill 的角色定义）。这三者常组合使用，故一并纳入。

借鉴点：如果你要做独立站（第 03 号方案里的"品牌层"），这个 MCP 能让你用自然语言管理商品与订单。MIT 许可 + 238 星 + 活跃维护，是这批 MCP 里最成熟的一个。Shopify 2026-01 的认证变更它也跟上了，说明维护质量可信。

最重要的一条：缺口即机会

整个生态里没有任何仓库在做「食品/农产品出口目的国准入」。原因不难理解：这个领域的知识更新快（欧盟 MRL 每年改、新烟碱 2026-03 降限、2027 有机高风险清单）、需要一手官方来源、且各国差异极大 —— 通用仓库不愿意维护这种高时效成本的知识。

而这恰好是本项目已掌握的内容：前两份报告里的合规内容，本身就是稀缺资产。把它结构化成一个 SKILL.md（比如「茶叶出口合规检查」），配上一份「目的国准入对照表」的 references，就是一个这个生态里还不存在的东西。这不是"做工具替代做正事"—— 它是把已经做过的正事（合规调研）沉淀成可复用的资产。

05技术栈与架构共性 TECH PATTERNS

结构共性

Markdown 驱动

几乎全部是 SKILL.md + references/ + templates/ + scripts/ 的目录结构。SKILL.md 写「什么时候用、怎么做、输出什么」，references 放知识，scripts 放 Python/Node 工具。改的就是自然语言文档，不需要复杂工程能力。

数据层共性

MCP 取数

数据几乎都通过 MCP Server 接入：Shopify Admin API、Amazon SP-API、Sorftime/卖家精灵/SIF 等第三方数据源。Skill 管流程，MCP 管数据 —— 这是标准分工。

分发共性

自然语言安装

主流做法是「把仓库地址发给 AI，说'帮我安装'」，由 AI 读取仓库并写入对应工具目录。部分仓库（如 clawec-agents、cross-border-selection-kit）带 install.sh 或 installer skill 做自动化。门槛低到不需要命令行。

06落地建议 ACTION PLAN

第一步 · 建立认知（半天）
读 hikari0511/awesome-amazon-ec-skills 的「什么是 Skill / Plugin / MCP」概念表（CC0，可自由参考），搞清楚三者的分工。这是最高性价比的入门。
第二步 · 装两个即用工具（1 天）
装 chnjames/tradehot-skill（关税/准入/情报巡检）和 AccioWork/agent-skills 的关税计算器（MIT-0，CN→US 关税与 HS 编码查询）。这两个直接补上你合规与定价环节最实操的部分。
第三步 · 抄方法论，不抄代码（1 周）
精读 markwaveio/cross-border-selection-kit 的「三源交叉验证 + 六维打分 + 污染自检」和 noique/cross-border-ecommerce-skills 的 13 链结构。只学设计思路（两者许可都不明确），把方法迁移到"验证某款茶在某个市场有没有需求"上。
第四步 · 补生态空白（2–4 周）
把前两份报告里的合规内容（欧盟 MRL、FDA FSVP、日本肯定列表、标签要求）结构化成一份自己的 SKILL.md + references/。参考 zach22-1999/amazon-skills（MIT）的组织方式。这是这个生态里目前没人做的事。
第五步 · 独立站与风控（放量前）
做独立站时用 GeLi2001/shopify-mcp（MIT，238⭐）管理商品订单；首次大额合作前用 wo9230/osint-agent 给海外买家做一次背调。

6.1 三个不要

  • 不要一次性装一堆。这批 skill 里很多是个人项目、维护质量参差。先装 2 个验证可用，再逐步加。
  • 不要把"装了工具"当成"做了事"。这些 skill 是杠杆，不是替代品。选品结论、合规判断、定价决策，最终仍要你自己核。
  • 不要忽略许可证。商用前先确认，别拿 1302⭐ 的仓库直接进产品。
